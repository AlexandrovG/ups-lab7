# Лабораторная №6 — запуск и проверка

**Тема:** `uninterruptible_power_supplies` — источники бесперебойного питания.  
**Основные поля:** `capacity` (ёмкость, А·ч), `max_current` (максимальный ток, А).  
**Поиск:** `GET /api/uninterruptible-power-supplies?min_capacity=...&max_capacity=...`.

## Что сделано в проекте

- Палитра из задания: кнопки `#1F2429`, hover `#374151`, фон `#FFFFFF`, текст `#1F2429`/`#6B7280`, карточки `#F4F5F7`/`#E2E5E9`, навигация `#1F2429` с активным белым пунктом и остальными `#9CA3AF`.
- Убран CORS-middleware Go. Vite Proxy: `/api` → `http://localhost:8080`, `/s3` → `http://localhost:9000` (префикс `/s3` снимается).
- **Вход/выход только через обычный `axios`, без thunk и кодогенерации.** После входа вручную обновляется `auth` в Redux, JWT сохраняется в `localStorage`.
- **После F5 Redux вновь считает пользователя гостем**, сохранённый JWT остаётся для демонстрации в `Application` и Postman. Автоматического использования JWT из localStorage нет. Для повторного входа нужно опять нажать «Вход».
- Данные каталога загружаются через сгенерированный Axios API (`src/api/Api.ts`) из thunk Redux. Значения фильтра берутся из Redux.
- Mock-объекты показываются **только гостю и только при отсутствии сетевого соединения** с API.
- Добавление: создаётся черновик, затем публикуется услуга; изображение и видео передаются во вторую операцию. Если публикация не удалась, черновик не пропадёт.
- Лайки и удаление отправляют реальные запросы к Go; удаление разрешено только владельцу. AJAX блокирует интерфейс, пока запрос выполняется.
- В Go bucket MinIO создаётся автоматически (при наличии прав), для показа изображений публичным посетителям ставится только `s3:GetObject` policy. Загрузка выполняется с учётными данными сервера.

## Последовательность запуска (Windows PowerShell)

Для запуска требуются **Docker Desktop**, **Node.js с npm** и **Go версии не ниже 1.27.1** (требование `go.mod`). Наличие Go 1.23.x недостаточно. Для Windows выполните:

1. Откройте терминал в `office-ups-sprint-6-backend` и скопируйте конфигурацию:

   ```powershell
   Copy-Item .env.example .env
   docker compose up -d
   ```

   Значения в `.env.example` — только локальные учебные учётные данные. Для другого окружения замените пароли и JWT_SECRET. Подождите готовности PostgreSQL, Redis, MinIO.

2. В этой же папке бэкенда:

   ```powershell
   go run ./cmd/migrate
   go run ./cmd/uninterruptible_power_supply_service
   ```

   Go-сервер доступен по `http://localhost:8080`, Swagger — `http://localhost:8080/swagger/index.html`.

3. В новом терминале откройте `office-ups-frontend-sprint-6-redux-auth`:

   ```powershell
   npm ci
   npm run build
   npm run dev
   ```

   React открывается по `http://localhost:3000`. Только при таком способе запуска действует dev proxy `vite.config.ts`.

4. Зарегистрируйте тестового пользователя через Postman или PowerShell (пример логина и пароля измените):

   ```powershell
   $body = @{login='student6';password='LocalPassword123!'} | ConvertTo-Json
   Invoke-RestMethod -Uri 'http://localhost:3000/api/auth/register' -Method Post -ContentType 'application/json' -Body $body
   ```

   Затем входите этими данными в приложении. При повторной регистрации существующего пользователя может быть HTTP 409 — это ожидаемо.

5. После запуска всех сервисов проверьте интеграцию:

   ```powershell
   npm run verify-lab6
   ```

   Тест создаёт отдельного пользователя и две временные услуги с различными изображениями, проверяет маршрут `/s3`, фильтрацию по ёмкости, `is_creator`, лайк, удаление, выход и блокировку отозванного токена. Напечатает `LAB6 INTEGRATION CHECK: ... checks passed` только если все проверки успешны. При ошибке выведет конкретный сбой.

   **Важно:** этот интеграционный тест невозможно было выполнить в среде подготовки архива, поскольку нет запущенных PostgreSQL/Redis/MinIO и нет установленного требуемого Go + npm-пакетов. Его результат в вашем окружении ещё не известен.

## Как показать 16 скриншотов преподавателю

| № | Что сделать |
|---|---|
| 1–2 | Остановить только Go-сервис (Docker базы можно оставить), выйти из профиля; открыть плитку и ленту с mock (пояснение «демонстрационный режим»). |
| 3–4 | Запустить Go; открыть реальные карточки из PostgreSQL в плитке и ленте. |
| 5 | Открыть «Добавление», войти и заполнить название, описание, ёмкость, максимальный ток, фото. |
| 6 | Показать страницу логина с прямым Axios-запросом. |
| 7–8 | В Adminer `http://localhost:8081` поменять `capacity` опубликованной услуги, выполнить поиск/обновить плитку. На подписи писать именно «ёмкость», не «цена». |
| 9 | Войти, нажать F5; открыть Redux DevTools (`auth.isAuthenticated=false`) и Application → Local Storage (`token` остался). **Не публикуйте настоящий JWT в открытом отчёте**: замаскируйте значение токена на скриншоте. |
| 10 | Скопировать JWT из Application и отправить из Postman `GET http://localhost:3000/api/uninterruptible-power-supplies` (или напрямую на `8080`) с `Authorization: Bearer ...`. Показать **JSON** и `is_creator: true`, не HTML Adminer. |
| 11–12 | Показать `src/store.ts`, `src/slices/authSlice.ts`, `src/slices/upsSlice.ts`, `src/api/Api.ts` и `src/api/index.ts`. |
| 13–14 | Показать `fetchUpsList` в `src/slices/upsSlice.ts`, вызывающий `api.uninterruptiblePowerSupplies.uninterruptiblePowerSuppliesList`, и содержимое сгенерированного `src/api/Api.ts`. |
| 15–16 | Chrome DevTools → Network, успешные `GET http://localhost:3000/api/...` и `GET http://localhost:3000/s3/ups-media/...` со статусом 200 и корректным `Content-Type`. |

В исходном отчёте рисунок 10 показывал **HTML от Adminer**, а рисунок 16 лишь адрес в коде — для сдачи эти скриншоты необходимо переснять. В приложенном обновлённом Word-файле старые скриншоты сравниваются с исправленным исходным кодом, а локальный HTML/CSS-предпросмотр явно подписан как визуализация, не как запущенный сервер.

## Кодогенерация Swagger

Сгенерированный файл `src/api/Api.ts` уже приложен. Чтобы сгенерировать его заново, держите каталоги рядом, как показано выше, затем в каталоге фронтенда:

```powershell
npm run generate-api
```

Команда использует `../office-ups-sprint-6-backend/docs/swagger.json`, `swagger-typescript-api`, клиент `axios`. После изменения Swagger надо пересоздать файл API и проверить TypeScript-методы в thunk. Для входа/выхода этот клиент не используется.
