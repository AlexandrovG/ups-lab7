# ЛР №7 — запуск под Windows и 17 демонстрационных скриншотов

Тема: **Источники бесперебойного питания (ИБП)**. Установочная палитра сохранена:
кнопки и навигация `#1F2429`, фон `#FFFFFF`, карточки `#F4F5F7`.

## Прежде чем начать: два разных режима!

| Режим | Где работает | Какие данные | Команда сборки |
| --- | --- | --- | --- |
| GitHub Pages | На телефоне, HTTPS через GitHub | **Только 5 локальных mock-ИБП**, без бэкенда | `npm run build:pages -- ups-lab7` |
| LAN HTTPS | На телефоне в Wi-Fi ноутбука | **Реальные ИБП** из Go/PostgreSQL/MinIO | `npm run build:lan` |
| Разработка | На ноутбуке, Vite :5173 | Реальный Go через `/api`, MinIO через `/s3`; при отключении Go гость видит mock | `npm run dev` |

GitHub Pages физически не размещает Go-сервис. **Для показа «логин на телефоне» использовать LAN HTTPS, а не Pages.**

## 0. Распаковка и подготовка

1. Скопировать папку старого проекта `C:\lab6` для резервного хранения.
2. Распаковать ZIP так, чтобы рядом лежали папки `office-ups-sprint-6-backend` и `office-ups-frontend-sprint-6-redux-auth`.
3. Открыть в VS Code. Использовать Node.js 24, Go версии из `go.mod`, Docker Desktop.
4. Сертификаты **не вложены**: создаются локально на ноутбуке. Никакие `.pem` с приватными ключами не загружать в GitHub.

```powershell
cd C:\lab6\office-ups-frontend-sprint-6-redux-auth
```

Vite: `http://127.0.0.1:5173`. Порт `3000` ранее был занят Apache! Не используй его. В `vite.config.ts` `/api` направлен на `http://[::1]:8080` (IPv6), а `/s3` — на MinIO `http://127.0.0.1:9000`. Если вернётся Apache 404, проверь сетевые адреса, не меняй CORS в Go.

Проверка через PowerShell **без Markdown-скобок в URL**:

```powershell
$site='http://' + '127.0.0.1:5173'
Invoke-RestMethod -Uri ($site + '/api/uninterruptible-power-supplies')
```

`[]` при HTTP 200 означает пустую БД, а не поломку. Для наполнения можно использовать ранее подготовленный `seed_5_ups.mjs` или форму создания ИБП.

## 2. GitHub Pages: развернуть пять mock-карточек

1. На [github.com](https://github.com) создать **публичный репозиторий `ups-lab7`** (или другое имя, тогда нужно учитывать его в базовом пути).
2. **В корень этого репозитория** загрузить содержимое папки `office-ups-frontend-sprint-6-redux-auth`, а НЕ всю папку `C:\lab6`. В корне GitHub должны быть `package.json`, `index.html` и `.github/workflows/pages.yml`.
3. Удобно отправить из PowerShell (требуется Git):

```powershell
cd C:\lab6\office-ups-frontend-sprint-6-redux-auth
git init
git branch -M main
git add .
git commit -m "Лабораторная 7: PWA и адаптивность"
git remote add origin https://github.com/ВАШ_ЛОГИН/ups-lab7.git
git push -u origin main
```

**Не копируй строку с `ВАШ_ЛОГИН` буквально:** подставь логин GitHub. Если репозиторий уже подключён, `git remote add origin` повторно не выполняется.

4. Открыть репозиторий → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
5. Во вкладке **Actions** проверить успешное выполнение `Publish UPS mock PWA on GitHub Pages`.
6. Открыть `https://ВАШ_ЛОГИН.github.io/ups-lab7/` в браузере телефона. Страница показывает **5 mock-ИБП** без Go.
7. Chrome Android: меню `⋮` → **Установить приложение** (или «Добавить на главный экран»). Запустить с иконки.
8. Проверить фильтр: ёмкость от `1400`, до `2200`; открыть карточку → Подробнее → «← Каталог». Значения должны остаться в полях; отфильтрованный список не должен сброситься.
9. После первого успешного открытия PWA выключить интернет на телефоне и повторно открыть — оболочка и mock-карточки должны быть доступны через Service Worker.

Для локальной проверки сборки Pages без GitHub (только проверить артефакт):

```powershell
cd C:\lab6\office-ups-frontend-sprint-6-redux-auth
npm run build:pages -- ups-lab7
npm run verify-lab7
```

GitHub Actions делает сборку автоматически при `git push`, поэтому загружать готовый `dist` в GitHub не нужно.

## 3. HTTPS на Node.js и телефон через IP ноутбука

Телефон и ноутбук должны быть в **одной Wi-Fi сети**, не в гостевой сети с изоляцией клиентов.

1. Открой PowerShell, набери `ipconfig`. Узнай IPv4-адрес Wi-Fi ноутбука, например `192.168.1.42`. **Это пример, подставь настоящий.**
2. Установи **mkcert** с официальной страницы https://github.com/FiloSottile/mkcert/releases. Если пакет установлен через менеджер, убедись, что `mkcert -version` работает. `npm install -g mkcert` — это не обязательно тот же официальный исполняемый файл, лучше использовать официальный бинарник.
3. Создай локальный корневой сертификат доверия и сертификат для своего IPv4:

```powershell
cd C:\lab6\office-ups-frontend-sprint-6-redux-auth
mkcert -install
mkcert -cert-file certs\lab7.pem -key-file certs\lab7-key.pem localhost 127.0.0.1 ::1 192.168.1.42
mkcert -CAROOT
```

4. **Не передавай `rootCA-key.pem` и `certs\lab7-key.pem` никому**. Для доверенного HTTPS на Android нужно импортировать ТОЛЬКО `rootCA.pem` с ноутбука на телефон: Android → Настройки → Безопасность → Дополнительные настройки безопасности → Шифрование и учётные данные → Установить сертификат → сертификат CA (названия меню отличаются). Устанавливай только свою локальную CA; после демонстрации её можно удалить. Если браузер не доверяет сертификату, PWA-установка или защищённые возможности могут не работать; не игнорируй предупреждение.
5. Собери реальный React с API (НЕ сборку `build:pages`):

```powershell
npm run build:lan
npm run verify-lab7
npm run serve:https
```

6. Node на порту 8443 выдаст адрес вида `https://192.168.1.42:8443/grid`. Введи его в Chrome телефона. Важно **https** и IP ноутбука, не `127.0.0.1` на телефоне.
7. Если телефон не подключается, проверь сетевой профиль Wi-Fi Windows и разреши TCP порт 8443 в Windows Defender Firewall (желательно только для частных сетей): открой PowerShell **от имени администратора** и выполни:

```powershell
New-NetFirewallRule -DisplayName 'UPS Lab7 HTTPS 8443' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443 -Profile Private
```

8. Проверь на телефоне вход, плитку с реальными услугами и страницу подробностей. Axios направляется на **тот же https-origin**, Node проксирует `/api` на Go :8080, а `/s3` в MinIO :9000. **CORS на Go менять не надо**.
9. После изменения IP ноутбука **перевыпусти сертификат** для нового IP, а также проверь правило Windows Firewall.

Если порт 8443 занят: запускай ` $env:LAB7_PORT='9443'; npm run serve:https ` и открывай `:9443`.

### Проверка HTTPS через DevTools

На ноутбуке открой `https://localhost:8443/`, проверь значок настроек сайта → «Соединение защищено», вкладку **Security** → «View certificate». В коде HTTPS находится в `scripts/https-proxy.mjs` (параметры `cert`, `key`, `https.createServer`). Для телефона скриншот сделай в Chrome по IP ноутбука — страница должна открываться без предупреждения о недоверенном сертификате.

## 6. Проверка по контрольным вопросам

- **Flux:** однонаправленный поток данных: действие → состояние → перерисовка.
- **Redux:** `store` хранит состояние, `dispatch(action)` передаёт действие, `reducer` вычисляет новое состояние. `createAsyncThunk` выполняет асинхронный код через middleware.
- **PWA:** сайт с `manifest.webmanifest` + Service Worker; устанавливается на экран и может работать офлайн.
- **Tauri / native / hybrid:** Tauri оборачивает web UI в нативное desktop-приложение, PWA работает через браузер, нативное приложение использует SDK целевой ОС.
- **GitHub Pages:** статический хостинг HTML/CSS/JS по HTTPS, **не** сервер Go/PostgreSQL.
